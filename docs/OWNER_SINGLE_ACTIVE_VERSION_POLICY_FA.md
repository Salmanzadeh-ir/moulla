# سیاست دائمی مالک: یک نسخه فعال برای «پای منبر مولا»

**صادرکننده:** مالک مخزن `Salmanzadeh-ir/moulla` — ۲۰ نوامبر ۲۰۲۶  
**موضوع:** مدیریت نسخه، یکپارچگی، نسخه آزمایشی، تصویب، پشتیبان مستقل و پاک‌سازی قابل‌حسابرسی  
**وضعیت:** فرمان صریح مالک برای سیاست‌های آینده. این سند مجوز حذف فوری یا تغییر APK و امضای رسمی نیست.

## ۱. تنها منبع فعال

- **فقط `main` مرجع فعال توسعه** است. در زمان ایجاد این سند، نسخه مورد تأیید و ادغام‌شده `v119`، با مبنای Commit `ca1dd669f181e328071567b3e41b4bf06744895b` است.
- نسخه‌های قدیمی، برچسب‌های انتشار، تاریخچه Git، snapshotها و شاخه‌های آزمایشی تا طی فرایند پشتیبان‌گیری و حذف **مرجع فعال نیستند**. وجود آن‌ها مجوز کپی کور قابلیت‌های قدیمی به سورس جاری نیست.
- قفل فعال `design/owner-v119-main-app-lock.json` شامل **۱۸۲ فایل app** است و `scripts/verify_owner_v119_lock.py` آن را کنترل می‌کند. هر نسخه آینده فقط با مجوز مالک، قفل فعال نسخه جدید را جایگزین می‌کند؛ قفل‌های تاریخی تغییر نمی‌کنند.
- بخش‌های تاییدشده، فونت، چیدمان، لوگو، تصویر، ۹۳ عکس‌نوشته، محتوای نهج‌البلاغه و اصول کافی، دوره ۱۰۱۹ صوت، شرط دوسوم، یادداشت‌های متصل، پیشرفت و موقعیت صوت، ناوبری، مصرف صوت تنها پس از Play و یادآوری‌های تفأل/دوره باید باقی بمانند. برای هر قابلیت قدیمی، نبود معادل جدید ابتدا مستند و با مالک حل شود؛ بازگردانی کور ممنوع است.

## ۲. چرخه الزامی هر نسخه

`main` تاییدشده ← شاخه موقت جدا ← تغییر محدود و مجاز ← بررسی تفاوت با مبنا و تمام قابلیت‌های تاریخی لازم ← قفل جدید و آزمون واحد/رگرسیون/ساخت اندروید ← APK آزمایشی با **شناسه مستقل فقط روی runner** ← آزمون گوشی Android قدیمی و Android 13+، مجوزها، خاموشی/ریبوت، پخش، اینترنت، یادداشت، ارتقای داده ← **تایید صریح مالک برای همان APK و SHA** ← PR و سبزبودن CI ← ادغام در `main` ← پشتیبان کامل بیرون مخزن اصلی و آزمایش بازیابی ← برنامه پاک‌سازی دقیق و تایید جداگانه نام شاخه/تگ/Release توسط مالک ← پاک‌سازی مشروط ← آزمون دوباره و گزارش حسابرسی.

- قبل از تایید APK جدید، نسخه فعال قبلی در `main` دست‌نخورده می‌ماند؛ APK خروجی CI به‌تنهایی تایید نیست.
- فایل‌های `app/build.gradle` و `AndroidManifest.xml`، شناسه نصب رسمی، امضا، keystore، GitHub Secrets و APKهای بازار فقط با مجوز جداگانه مالک قابل تغییرند. ساخت Debug از شناسه جدا، بدون Secrets رسمی، در محیط موقت انجام شود.
- پس از ادغام، **فقط `main`** در README و راهنمای ساخت به‌عنوان نسخه فعال معرفی شود؛ شاخه‌ها/تگ‌های نسخه‌های پیشین تنها تاریخی‌اند.
- ثبت تایید مالک باید شامل Commit مبنا، SHA APK، Run ID، تاریخ و نسخه اندرویدِ آزموده‌شده باشد. تایید کلی یا شفاهی برای حذف نسخه‌ای کافی نیست.

## ۳. ضوابط غیرقابل‌دورزدن حذف

هیچ حذف خودکاری بدون **تمام** شرایط زیر مجاز نیست:

1. فهرست کامل شاخه‌ها، تگ‌ها، Releaseها، APKها، فایل‌های نسخه‌ای و شناسه Commit هر هدف موجود و با `main` مقایسه شده باشد؛ داده/قابلیت لازمِ منحصربه‌فرد و استفاده‌نشده نباید از بین برود.
2. پشتیبان **مستقل از مخزن اصلی و مستقل از شاخه GitHub دانلود** شامل Git history و همه refs (`git clone --mirror` یا bundle بازیابی‌پذیر)، تگ‌ها، سورس، اسناد، APKهای نسخه‌ای، Release assets و گزارش‌ها تهیه شده باشد.
3. برای هر پشتیبان شناسه نسخه، فهرست مسیر/حجم، **SHA-256 بایت‌به‌بایت** و محل نگهداری مستقل ثبت شود؛ از فضای بیرونی دانلود و در محیط جدا بازیابی شده و با هش/refs تطبیق شده باشد. GitHub Actions Artifacts محدودبه‌زمان یا شاخه دیگر در **همان مخزن** جایگزین این شرط نیست.
4. آخرین `main` و تمام قفل‌ها و CI سبز باشد؛ پس از تایید نسخه نهایی مالک، **فهرست دقیق اهداف حذف** نیز جداگانه تایید شده باشد. تایید APK یا تایید این سیاست، تایید حذف نامعین نیست.
5. تنها نام‌های مجازِ دقیق، روی SHAهای پیش‌بینی‌شده حذف شوند؛ تغییر SHA از زمان گزارش = **توقف**. `main`، شاخه فعال جدید، شاخه/تگ/Release در حال استفاده، فایل مشترک، امضا و منابع رسمی محافظت می‌شوند. هر ابهام یا خطای شبکه/آزمون/بازیابی = **عدم حذف**.
6. تگ‌ها و GitHub Releaseها فقط با اجازه **موردی و صریحِ نسخه‌به‌نسخه**؛ نسخه بازار و بازنویسی تاریخچه/Force-push ممنوع.
7. بعد از حذف، آزمون واقعی ساخت و قفل نسخه فعال تکرار و گزارش با لینک Commit/Actions و لیست حذف‌شده‌ها منتشر شود. حذف قابل جبران با بازگردانی از پشتیبان مستقل باشد.

## ۴. اجرای ماشینی و سطح دسترسی

- `scripts/owner_version_inventory.py`: گزارش فقط-خواندنی همه شاخه‌ها/تگ‌ها/Releaseها و مبنای `main`، SHA و طبقه‌بندی محافظه‌کارانه. خروجی قابل آرشیو JSON و Markdown.
- `scripts/owner_cleanup_plan.py`: **فقط پیشنهاد و عدم حذف**، هر شاخه مشکوک یا رسمی را نگه می‌دارد و شرط‌های اداری/پشتیبان را در گزارش «برآورده‌نشده» می‌نویسد.
- `.github/workflows/owner-version-governance.yml`: با دسترسی `contents: read` این بررسی را اجرا و گزارش را به‌عنوان Artifact پژوهشی، نه پشتیبان مستقل، ثبت می‌کند. وجود گزارش = مجوز حذف نیست.
- پاک‌سازی عملی تا ثبت و آزمون مقصد خارج از مخزن، تکمیل بازیابی، مجوز فهرست هدف‌ها و ساخت Workflow جداگانه با دسترسی کوتاه‌مدت و محدود **غیرفعال** می‌ماند. هیچ Workflow جاری با دسترسی نوشتن، حذف خودکار شاخه/Release/Tag انجام نمی‌دهد.
- GitHub Rulesets باید با دسترسی مدیریتی GitHub برای `main` و تگ‌های حیاتی فعال شود: الزام PR و `verify-ui-lock`، جلوگیری از Force-push و Deletion و توجه به این نکته که مالک تنها نباید به‌دلیل الزام تأیید شخص دوم از ادغام محروم گردد. تا بررسی API موفق، این حفاظت را برقرارشده اعلام نکنید.

## ۵. مرز نسخه رسمی و داده کاربر

- سورس `main` نسخه فعال **توسعه** است و به‌معنای انتشار رسمی در بازار نیست؛ APK رسمی و امضا دست‌نخورده می‌مانند تا مجوز مشخص صادر شود.
- Debug با شناسه جدا، `localStorage` و پایگاه داده نصب رسمی را به‌صورت خودکار به اشتراک نمی‌گذارد. آزمون مهاجرتِ واقعی فقط روی مسیر نصب با applicationId/امضای سازگار معنا دارد.
- تفاوت اندروید ۱۳+ در `POST_NOTIFICATIONS`، حالت Doze، محدودیت باتری، ساعت محلی و باززمان‌بندی باید روی دستگاه بررسی شود. موفقیت تست‌های واحد ضمانت تحویل دقیقه‌ای Alarm نیست.
