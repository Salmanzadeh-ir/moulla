## راستی‌آزمایی عملی پشتیبان

- [اجرای موفق GitHub Actions شماره 44686986438](https://github.com/Salmanzadeh-ir/moulla/actions/runs/44686986438) پشتیبان قدیمی را از [Artifact تهیه‌شده برای گوشی](https://github.com/Salmanzadeh-ir/moulla/actions/runs/44678498751/artifacts/14603476394) دوباره دریافت کرد.
- ZIP اصلی `PayeMenbareMola-COMPLETE-OWNER-BACKUP-44678498751.zip` با **SHA-256 `2b32807107ac7d44cbecb74881d51a42d452bb4201e17bf0b73d5909e1362a07`** و بررسی ZIP موفق دوباره کنترل شد. تست بازیابی Mirror و تمام refs در اجرای اصلی ساخت پشتیبان انجام شده بود.
- مالک در گفتگو اعلام کرد پشتیبان اصلی **کامل روی گوشی دانلود شد**؛ اما **هش SHA-256 خود نسخه ذخیره‌شده روی گوشی** با ابزار مستقلی هنوز تأیید نشده است. ادعای تأیید بایت‌به‌بایت روی گوشی نکنید.
- پشتیبان مربوط به هنگام تهیه، **۸۰ شاخه** داشته و Commit `main` آن `d811536ca2bf7f630eb450a30e1d17d31f6d4bc9` است؛ تغییرات و شاخه‌های جدید بعد از آن در این ZIP موجود نیستند.

### قاعده طبقه‌بندی ۲۹ نامزد

- همه ۲۹ نامزد فقط «`REVIEW_CANDIDATE_ONLY`»اند و **هیچ‌کدام اکنون مجوز حذف ندارند**.
- SHA فعلی و SHA پشتیبان آن‌ها یکسان است؛ این فقط **شرط لازم**، نه شرط کافی برای حذف است.
- شاخه‌های `main`، انتشار، Snapshot، تحویل مالک، APK download (به‌ویژه لینک عمومی v119)، شاخه آزمایشی v120/v121، ماژول‌های قدیمی v108/learning که هنوز همه امکاناتشان منتقل نشده، و سرشاخه‌های دو PR باز محافظت شده‌اند.
- تگ‌ها و Releaseهای تاریخی حتی در فهرست ۲۹ مورد نیز نیستند؛ مجوز جداگانه و **نام دقیق هر تگ/Release** برای حذف لازم است.

## چرا هنوز حذف نکرده‌ایم؟

۱. نسخه آزمایشی یکپارچه v121 در شاخه مستقل با ۱۹۵ فایل قفل‌شده، ۱۰۵ تصویر و ابزارهای اختیاری حکمت ساخته و در [GitHub Actions Run 44686143758](https://github.com/Salmanzadeh-ir/moulla/actions/runs/44686143758) سبز شده است؛ **هنوز همان APK با SHA `f5d0092f1c821ea5c85dc7fb57c999d54407aacb0359819b6a682f9c142ccdb2` روی گوشی مالک صریحاً تأیید نشده است**. مطابق فرمان مالک، v119 باید تا آن هنگام تنها نسخه فعال در `main` بماند.
۲. قابلیت‌های آزمایشی Native قدیمی مانند کش MP3، پخش پس‌زمینه اختیاری و تایمر خواب هنوز معادل‌سنجی/تأیید نهایی نشده‌اند و صرف وجود نام branch تایید دستگاه نیست.
۳. نیاز است پشتیبان تازه از **تمام تغییرات جدید و HEAD کنونی** با بازیابی و SHA بایت‌ها خارج مخزن تهیه شود.
۴. مالک طبق فرمان دائمی، باید **فهرست مشخص و نام‌به‌نام اهداف حذف** را پس از تمام تست‌ها جداگانه تایید کند. تأیید کلی سیاست یا اعلام دانلود فایل مجوز حذف نامعین نیست.
۵. Rulesets اجباری `main` در API خالی بود و اتصال GitHub برای فعال‌سازی اداری آن اختیار ندارد؛ تغییر این تنظیم در GitHub Settings به اقدام مالک نیاز دارد.

## چطور با کمترین دخالت مالک ادامه دهیم؟

- ابتدا با APK آزمایشی v121 روی گوشی، ۱۰۵ تصویر، نشانک/یادداشت حکمت، بازگشت و پخش صوت و اعلان را آزمایش کند؛ **به نسخه رسمی بازار دست نزند**.
- برای تصدیق واقعی پشتیبانِ موجود روی گوشی، SHA-256 فایل ZIP با مقدار بالا مقایسه شود؛ داشتن صرفاً نام یکسان کافی نیست.
- بعد از تأیید v121 و تکمیل تعیین تکلیف امکانات قدیمی Native، درخواست ادغام از طریق PR و CI + قفل جدید انجام شود.
- سپس یک پشتیبان تکمیلی شامل HEAD/شاخه‌های تازه ساخته، در محل مستقل بازیابی و آزموده و نام دقیق ۲۹ نامزد توسط مالک تأیید شود؛ تازه بعد، حذف محدود و آزمایش پس از حذف مجاز است.

**هیچ نسخه اصلی، تصویر یا محتوای فعلی و هیچ خروجی رسمی حذف نشده است.**
