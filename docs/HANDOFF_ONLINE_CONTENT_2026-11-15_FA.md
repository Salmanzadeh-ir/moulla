## ۴. وضعیت سرور واقعی Cloudflare
- پنل زنده: https://pmm-content-updates.kazeminia-mohamad110.workers.dev/admin
- Worker: pmm-content-updates.
- KV Namespace: pmm-content-data؛ binding دقیق Production: PMM_CONTENT.
- Secrets دقیق Production: PMM_ADMIN_PASSWORD (حداقل ۱۶ کاراکتر) و PMM_SESSION_SECRET (حداقل ۳۲ کاراکتر).
- رمزهای واقعی قابل بازیابی/مشاهده در داشبورد نیستند و هرگز در مخزن، APK یا این گزارش قرار نمی‌گیرند.
- مالک عکس صفحه فارسی پنل و سپس ورود موفق را فرستاد. پس ثبت Worker، اعتبارسنجی رمز و خواندن فهرست خالی KV عملیاتی و تأییدشده‌اند؛ در زمان تصویر: نسخه محتوا ۰ و تعداد مطالب ۰.
- پیش‌تر پیام «رمز مدیریت تنظیم نشده» رخ می‌داد، چون مقدار رمز مدیریتی کوتاه‌تر از ۱۶ کاراکتر وارد شده بود. پس از جایگزینی مقدار کافی و Deploy، ورود موفق شد. مقدار رمز قدیمی در عکس گفتگو دیده شد و نباید دوباره استفاده شود.
- Cloudflare R2 به دلیل نخواستن اشتراک مالی توسط مالک فعال نشد. تصاویر تازه در همان Workers KV، با کلیدهای media:UUID و metadata نوع تصویر ذخیره می‌شوند.
- برای صوت/فیلم، پنل لینک معتبر HTTPS ایتا/آپارات می‌گیرد؛ بارگذاری فایل صوت یا فیلم به KV فعلاً طراحی نشده است.
- پنل در مرورگر گوشی/ویندوز قابل استفاده است و جدا از برنامه مخاطب است.

## ۵. نقاط API و امنیت
- GET /admin: پنل فارسی
- GET /api/manifest: فهرست عمومی فقط خواندنی با schema=1، revision و items
- GET /media/UUID: تحویل آنلاین تصویر
- POST /api/login: ورود مدیر و cookie امن HttpOnly/Secure/SameSite
- GET /api/admin/state: وضعیت مدیریت، نیازمند نشست
- POST /api/admin/upload: عکس JPEG/PNG/WebP تا ۸MiB
- POST /api/admin/publish: انتشار و افزایش revision
- POST /api/admin/remove: حذف و افزایش revision
- POST /api/admin/logout: خروج
- فقط مسیرهای معتبر ایتا/آپارات پذیرفته می‌شوند و URL تصویر باید متعلق به همین Worker باشد.
- سقف فعلی ۳۰۰۰ آیتم و حدود ۱MiB برای فهرست است.
- با توجه به محدودیت Workers Free/KV، تعداد زیاد مخاطبان/خواندن تصویر می‌تواند به سقف رایگان برسد. هیچ طرحی نباید بدون اجازه مالک پولی شود. نسبت به صفرشدن مطلق کش سیستم‌عامل ادعایی وجود ندارد.
- کلید خصوصی امضای APK و رمزهای آن مطلقاً در گفتگو یا GitHub commit ذخیره نشوند.

## ۸. قدم‌های ادامه کار به ترتیب
۱. به‌صورت فقط‌خواندنی، endpoint عمومی /api/manifest را بررسی کنید؛ ابزار وب این گفتگو به workers.dev دسترسی مستقیم نداشت. اسکرین‌شات ورود موفق مالک موجود است.
۲. با اجازه مالک یک مطلب کوچک واقعی در پنل منتشر کنید و Manifest را بررسی کنید. بدون اجازه محتوای ساختگی به مخاطبان عمومی منتشر نکنید.
۳. محدودیت مصرف KV، هزینه صفر مورد نظر مالک، ایمنی نشست و تجربه انتشار را دوباره مرور کنید؛ در صورت نیاز تغییرات را فقط در شاخه ویژگی انجام دهید.
۴. APK آزمایشی شاخه توسعه را بسازید و روی گوشی واقعی: اعلان وسط نمای ایوان، «بعداً»، بازگشت، پذیرش، هر هفت بخش، عکس، و عدم ذخیره رسانه در گوشی را آزمایش کنید.
۵. پیش از ادغام PR و انتشار، تأیید صریح مالک بگیرید؛ مرجع V16 و نسخه رسمی ۱۰.۴.۹ نباید آسیب ببینند.
۶. Secrets امضای رسمی را فقط در GitHub Actions با روش امن تنظیم کنید؛ امضای release را با گواهی نسخه رسمی قبلی مطابقت دهید.
۷. APK Release امضاشده و ZIP توزیع را تولید، روی گوشی آزمایش و مستقل از مرجع V16 منتشر کنید.
