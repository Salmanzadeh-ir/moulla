## محدوده واقعی قفل و نحوه حفظ آن

این قفل، **قفل محتوایی و کنترلی Git + CI** است. کاربری که دسترسی نوشتن به فایل‌های بررسی دارد می‌تواند آنها را تغییر دهد، مگر اینکه محافظت مدیریتی نیز فعال باشد. بررسی API فعلی نشان داده است شاخه `main` هنوز `protected: false` است و Ruleset فعال ندارد.

برای قفل دسترسی واقعی، مالک باید در **GitHub → Settings → Rules → Rulesets**، محافظت از `main` و تگ مرجع را با الزام Pull Request، تأیید CODEOWNERS، موفقیت آزمون `verify-ui-lock`، منع حذف و force-push و محدودسازی bypass فعال کند. این اتصال ابزار دسترسی لازم برای فعال‌کردن RuleSet مدیریتی را ندارد. تا پیش از آن، نباید قفل را «غیرقابل تغییر از نظر دسترسی» معرفی کرد.

**هر تغییر مجاز آینده:** فقط پس از دستور جدید مالک، به‌صورت تغییر محدود و قابل‌ممیزی با بازبینی، آزمون و ثبت دوباره SHA-256 / قفل نسخه انجام شود.
