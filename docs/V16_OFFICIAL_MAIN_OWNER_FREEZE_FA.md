## تصمیم صریح مالک

مالک درخواست کرده نسخه V16، همان نسخه‌ای که از آخرین تغییرات ساخته و برای آزمایش ارسال شده، **نسخه اصلی سورس موجود در مخزن** باشد. محتوای فعال برنامه، همه هفت بخش منو، صفحات، عملکردها، فایل‌ها، متن‌ها، عکس‌ها، فونت‌ها، لینک‌ها، منطق برنامه و منابع جانبی نباید بدون **دستور صریح تازه مالک** تغییر، حذف، جابه‌جا یا جایگزین شوند. هیچ تغییر خودکار یا به‌روزرسانی ضمنی مجاز نیست.

این سند اعلام وضعیت نسخه اصلی است و **هیچ فایل `app/` یا رفتار برنامه را تغییر نمی‌دهد**.

## مبنای قفل فعلی

- تمام **۱۶۴ فایل** فعال در `app/`، همراه با جلوگیری از اضافه/حذف شدن فایل‌ها، طبق `design/v16-current-preview-lock.json` با هش Git blob منجمد شده‌اند.
- `scripts/verify_current_preview_lock.py` صحت مجموعه فایل و هش‌ها را بررسی می‌کند.
- `scripts/verify_v16_preview.py` موجودیت بخش‌های V16 و محتواها (هفت منو، ۴۸۹ حکمت آفلاین، ۹۳ عکس‌نوشته، فونت‌ها و ابزارها) را کنترل می‌کند.
- `.github/workflows/verify-layout-lock.yml` بررسی‌ها را روی PR و push به `main` اجرا می‌کند؛ وضعیت اجرای متناظر با commit مبنا: **success**.
- `.github/CODEOWNERS` مالک `@Salmanzadeh-ir` را برای تمام مسیرها ثبت کرده است.

## روش تغییر مجاز در آینده

تنها پس از دستور صریح تازه مالک: ایجاد شاخه تغییر جداگانه، بازبینی محدوده دقیق تغییر، آزمون برنامه و APK، ثبت مبنای قفل جدید با تأیید مالک، Pull Request و بازبینی مالک.

**محدودیت مهم:** هش‌ها و CI به‌تنهایی مانع کسی که اختیار تغییر مستقیم شاخه و فایل‌های CI دارد نمی‌شوند. برای قفل دسترسی لازم است مالک در Settings → Rules → Rulesets یا Branch protection برای `main`، الزام Pull Request، تأیید CODEOWNERS، موفقیت check `verify-ui-lock`، ممنوعیت force push و حذف شاخه و محدودیت bypass را فعال کند. این اتصال GitHub به تنظیمات مدیریتی حفاظت شاخه دسترسی نوشتن ندارد؛ تا زمان فعال‌شدن Ruleset نمی‌توان قفل غیرقابل‌دورزدن را ادعا کرد.
