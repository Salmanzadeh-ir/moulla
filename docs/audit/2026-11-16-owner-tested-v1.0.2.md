## یافته‌های باز (بدون تغییر دادن برنامه)

1. **اولویت بالا — حفاظت GitHub:** `main` در زمان ممیزی `protected=false` و فهرست Rulesets خالی بود. آزمون CI «قفل مالک» از نظر منطقی مفید است اما مانع قطعی Push، حذف شاخه یا تغییر workflow توسط صاحب دسترسی نوشتن نمی‌شود. برای محافظت اجرایی باید Branch protection/Rulesets فعال شود.
2. **اولویت متوسط — آزمون قدیمی V16:** اجرای `Verify owner-approved V16 sections and historical 10.4.9` در [run #43796887135](https://github.com/Salmanzadeh-ir/moulla/actions/runs/43796887135) **ناموفق** بود، چون `scripts/verify_current_preview_lock.py` پنج فایل جدیدِ مجاز (`Estedad-OFL.txt`, `Estedad-VF.woff2`, `nahj_audio_links.js`, `pmm_online_updates.css`, `pmm_online_updates.js`) را در فهرست قفل قدیمی نمی‌شناسد. در همان run آزمون `verify_v16_preview.py` موفق بود. این ناسازگاری ممیزی/CI است، نه مدرک خراب‌شدن نسخه قدیمی؛ اصلاح checker نیازمند مجوز جداگانه مالک است.
3. **اولویت متوسط — ماندگاری خروجی:** APK در GitHub Actions Artifact ذخیره شده و ممکن است در تاریخ انقضا حذف شود. متن/هش/منبع بازتولید در مخزن ثبت است، اما خود فایل APK به‌عنوان فایل باینری دائم در Git commit یا GitHub Release بارگذاری **نشده** است. ذخیره دائمیِ قابل دانلود، کار جداگانه و نیازمند اجازه/امکانات بارگذاری Release است.
4. **پیش از انتشار رسمی:** Debug امضای انتشار بازار نیست؛ ساخت Release امضاشده، بررسی پخش از سرور روی چند گوشی و تصمیم مالک درباره ۹ لینک غرائب الحدیث جداگانه است.
